# RCC Website SSG Prerender Architecture

## The rule
Two-step Vite build: (1) client build -> dist/public/, (2) SSR build -> dist/server/. Then scripts/prerender.mjs renders each route into per-route HTML.

**Why:** SPA shell emits empty <div id="root"> that search engines cannot index. Prerendering ensures full HTML content, canonical, hreflang, and JSON-LD are visible without JS.

**How to apply:**
- vite.config.ssr.ts is the SSR build config (no PORT/BASE_PATH check, ESM output to dist/server/)
- src/entry-server.tsx exports render(url): Promise<{html, metadata}>
- scripts/prerender.mjs reads dist/public/index.html, injects head + body, writes per-route index.html files
- Sitemap.xml is auto-generated by the prerender script from the ROUTES array
- PORT is optional during vite build (isBuildMode check added to vite.config.ts)
- main.tsx uses hydrateRoot when root has pre-rendered children, createRoot otherwise

## Known gotchas
- Lazy components (React.lazy) cause suspension in SSR lightweight pages; use direct imports in SSRHomePage/SSRPackagesPage
- The wouter Router in SSR needs a custom hook prop that returns the static URL string
- faqAssistant.ts needs Lang type from @/seo/routes, not Language from LanguageContext (type was renamed)
